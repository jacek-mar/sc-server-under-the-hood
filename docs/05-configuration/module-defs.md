> Generated by the maintainers' tooling from `data/gamedata/def/ex/*.lua`, `shared/item_subtypes.lua`, `cloud/data/store.xml` and the lifted `ai/cosmos_constants` (names/counts/numeric ranges only; no Lua bodies). ## 1. Pipeline and file families

All `def/ex/*.lua` files are flat exports (`Def.<name>.<field>=<value>`; namespaces `Def`, `Spell`, `DefItemPrice`, `RankBuff`, `VesselProgress`, `SpaceZone`) from designer spreadsheets (header: *generated by Targem Export script from file '...ods'*; every row has `ods_export=true`). Hand-written bases live in `def/objects/*.lua` (e.g. `Weapon_LaserGun`, `Module_Base`); the exported row sets `inherit = "<base>"` and overrides numbers.

Chain for a weapon: **weapon def** (`Weapon_*`: damage, rate, range, heat) -> `Projectile_*` def in `*_projectile.lua` (`spell = "Spell_*"`) -> **spell** in `*_spell*.lua` (`influence_param` = effect strength, `inherit` = spell base). Rockets use `*_blastwave.lua` rows for splash. `*_t.lua` rows are token/trade variants of the same module (`_RT`/`_ET`: `cant_be_equipped=true`, `tokenPrice`, `drop_weight`).

Modal `mark` value per suffix *(file)*: `Mk1` = 1, `Mk2` = 2, `Mk3` = 3, `Prem` = 4, `Rel` = 5, `Rare` = 6, `Craft` = 7, `Epic` = 7. So the quality ladder in numbers is Mk1 < Mk2 < Mk3 < Prem < Rel < Rare < Epic; the `Rare/Epic/Rel` rows are separate defs, not upgrades of the Mk chain. `ai.ModuleLevel` (INVALID=0, MK1=1, RARE=2, MK3=3, EPIC=4, REL=5) is a different, coarser enum used for upgrade levels (`curUpgradeLevel` 1-3 in `store.xml`). `_ET`/`_RT` rows live in the `*_t.lua` files with only a few fields (`cant_be_equipped`, `tokenPrice`, `drop_weight`) - event/reward-token variants. Exceptions with other mark values exist (a few dozen rows per suffix).

## 5. Price overrides

`def/module_prices.lua` runs the `prices_*.lua` exports (`DefItemPrice`) and, in `FixupDefItemPrices()`, **merges** each override row into the def of the same name **when that def has a non-zero `storeItemId`**. So the price in the weapon row is a placeholder and the effective numbers are in `prices_modules.lua` (10508 `DefItemPrice` rows in all prices files; 8069 of the 9581 module defs have one). Fields in override rows: `ods_export` (10508), `price` (9685), `premiumPrice` (8210), `source_desc` (2061), `is_atlas_entity` (1531), `outdated` (1272), `uiDesc` (1242), `tradePremiumPrice` (1034), `tokenPrice` (621), `source_zone` (542), `cant_be_bought` (446), `mastery_bonus` (413), `hull_damage_for_death` (413), `cred_reward_bonus` (413).

## 7. Editing consequences

* Weapon damage/rate/range: edit the `Def.Weapon_*` row (or its `Spell_*` `influence_param` for effect-type weapons) in the matching `def/ex/<class>.lua`; the DPS column is a derived spreadsheet value and **not** read back (⚠ verify), so change damage and rate, not `DPS`.
* Prices: edit `prices_modules.lua` (override rows), not the weapon row, or the merge will overwrite your number (when `storeItemId` is non-zero).
* After editing, regenerate shared data (`prepare_shared`) so that `store.xml` follows (Q36 for the exact procedure).
* Whether remote clients take the numbers from their own files (`data/gamedata` is part of the client install) or from the server is the open Q29/Q36 runtime question.
