# Quest system - semantics (generated)

> Generated by the maintainers' tooling from `data/gamedata/shared/quests.lua`, `quests_base.lua`, `cloud/data/quests.xml` and the lifted `ai/questconstants` (enum names and numbers only; no Lua bodies are reproduced). Do not edit by hand. Structure of the XML itself: [xml-schemas.md](xml-schemas.md#questsxml).

## 1. How the pieces fit

| Piece | Location | Role |
|---|---|---|
| Enums + group table | `data/gamedata/shared/quests_base.lua` | `QuestCategory`, `QuestGroupId`, `QuestGroups[..]` (offer/complete cooldowns), `QuestId` name -> numeric id |
| Quest definitions | `data/gamedata/shared/quests.lua` | one `Quests[QuestId.X] = {...}` per quest (conditions, rewards, UI hints) |
| Engine constants | `scripts/ai/questconstants.lua` (misc.pak, bytecode) | `ai.GameEvent`, `ai.GameEventParam`, `ai.QuestTag`, `ai.QuestBattleType`, allowed params per event |
| Server form | `cloud/data/quests.xml` | the same quests keyed by numeric `id` + `name`, read by QuestServer/Shard |
| Generator | `DedicatedServer.exe -prepareSharedData` (`prepare_shared.bat`) | produces the XML from the Lua (architecture §5) |

**Cross-check on the shipped build:** 820 quests in `quests.lua`, 912 in `quests.xml` (820 share a name; 92 XML-only, 0 Lua-only). `QuestId` has 882 names; XML has 71 groups and `quests.lua` base file 71 `QuestGroups[...]` entries. `421` XML quests carry `disabled="1"`.

Note: `quests.xml` has **two top-level elements** (`QuestGroups` and `Quests`) and is therefore not a single-root XML document; strict parsers need a wrapper.

Interpretation: the XML is the compiled server view of the Lua definitions (same names, numeric ids from `QuestId`). Fields that only exist in Lua are client/UI hints; fields that only exist in the XML are server-side additions (see §3). Which of the two files must be edited, and whether the XML is regenerated or must be kept in sync by hand, is **not decided by static inspection** - see open question Q36.

## 4. Practical notes

* A quest's reward in the **UI** is selected by the Lua `ui_reward` key; the server can grant several reward attributes at once (credits, gold credits, tokens, vessel exp, items). This is why community edits show only one reward.
* `intervalStartHour` / `intervalLongHours` / `intervalLongEnableHours` define recurring or one-off availability windows (ISO start + repeat).
* `requiredPveScheduledLevel` ties a quest to a PvE scenario name from the [level catalogue](level-catalogue.md).
* Edits: see [tuning-recipes](tuning-recipes.md) and Q36 - the generator relation above is the file-verified part; the exact edit order is untested.
