# Ship definitions - data model (generated)

> Generated by the maintainers' tooling from `data/gamedata/def/objects/ships.lua`, `data/gamedata/def/ex/ship*.lua`, `prices_ship.lua` and `cloud/data/store.xml`. Names, counts and numeric ranges only. Do not edit by hand. Answers B-7 and the static half of Q29 (where ship statistics come from).

## 1. Where ship data lives

| File (under `data/gamedata/def/`) | Defs | Content |
|---|---:|---|
| `objects/ships.lua` | 63 | hand-written **base classes** (`Ship_Base` -> `Ship_Small/Medium/Large/Huge` -> faction/variant bases); models, sounds, effects, slot bones; the inheritance roots |
| `ex/ship.lua` | 301 | exported (`Def.<ship>.<field>=`): the Race 1-3 ship lineup with stats |
| `ex/ship_green.lua` | 358 | exported: Race 5 ("green"/crystal) ships incl. progression links (`prev`/`next`, `node_prices`, `progress`) |
| `ex/ship_green_progress.lua` | 475 | `VesselProgress.*` nodes (exp, resources, evolution %) - different table, loaded for the green progression |
| `ex/prices_ship.lua` | 413 | `DefItemPrice.*` price/repair/mastery bonus per hull class+tier |
| `ex/ship_preset.lua` | 244 | default module presets (`default_modules`, `ship_def`, `ship4bot`) |
| `ex/ship_preset_e.lua` | 244 | preset variants with `*_mul` multipliers (`hull_health_mul`, `shield_max_mul`, `laser/plasma/railgun_damage_mul`) |

Every `ex/*.lua` header says *generated by Targem Export script from file '...ods'* (designer spreadsheets such as `Ship_Param_...ods`, `green_skin.ods`): the spreadsheets are the real source, the Lua files are their export, and an `ods_export=true` flag marks each row. For a community edition this means **stat changes belong in `def/ex/ship*.lua` (or a patch layer over it)**, and numbers there are the base values that module bonuses, progression and rank buffs are applied on top of.

## 5. Link to the store and the database

* `store.xml` has 659 `Vessel` rows; 659 of them have a row in `ship.lua` (301) or `ship_green.lua` (358). Only 428 rows carry a full stat block; the other 231 (mostly green evolution variants) only add links/prices and inherit statistics from their parent def.
* `storeItemId` in the Lua rows is a small sequence number (1..1101, 241 distinct values in 659 rows) and equals `store.xml` `Item@id` for 0 ships: it is an export-time counter, **not** the database id.
* **`fake = true` marks player ships, not placeholders** *(file, 2026-10-19)*: all 355 occurrences are in `ship_green.lua` and belong to the progression ships - Ellydium (`Ship_Race5_*`), Tester's Agony (`Ship_ST_*`), Salyut, Helicon and UFO - including their base definitions (e.g. `Ship_Race5_S_RECON_Rank5`, `ship_green.lua:5887`) and the per-rank variants named `<base>_Rank<r>_<n>` or `Ship_ST_Rank<r>_<ROLE>`. Every one of them has a `store.xml` `Vessel` row, and the base ranks are the ships players own and hosts grant. Counted as player ships, the build has 655 of them (301 in `ship.lua` + 354 in `ship_green.lua`; 4 more Ellydium definitions lack a complete set of evidence). What the engine does with `fake` is ⚠ unverified - do not filter player ships by it.
* `rank` agrees between Lua and `store.xml` for 428 of 428 comparable ships.
* Numeric ids used by the DB (`items` / ship documents) are `store.xml` `Item@id` *(inferred from schema.md/F5)*; `shared/def_ids.lua` is only a stub (`DefId = {}` with a commented sample) and holds no ids in this build.

## 6. Presets, prices and bot multipliers

* `ship_preset.lua`: 244 presets: `ship_def` = the ship they equip, `default_modules` = slot -> module, `default_rocket_munition`, `ship4bot=true` marks presets used by AI ships. Preset names are `<ship>_Preset<N>`; `Ship_PresetE_*` is a second family.
* `ship_preset_e.lua` multiplier values (all `ship4bot`): `hull_health_mul=0.1` x244, `laser_damage_mul=0.1` x244, `plasma_damage_mul=0.1` x244, `railgun_damage_mul=0.1` x244, `shield_max_mul=0.1` x244. Bot stat scaling therefore lives here (cross-reference Q28 and `bot_preset*.lua`).
* `prices_ship.lua` fields per hull class+tier: `ods_export` (413), `mastery_bonus` (413), `hull_damage_for_death` (413), `cred_reward_bonus` (413), `repair_cost` (408), `is_atlas_entity` (320), `price` (301), `premiumPrice` (94); 320 rows carry `is_atlas_entity=true` (their ids are allocated by `-prepareSharedData`, see store-zones-rules-semantics).

## 7. Practical consequences (Q29)

* Speed, energy, shields and hull are plain numbers in `def/ex/ship*.lua`; that is the file-verified source of base statistics.
* Damage comes from weapon/module defs (`def/ex/laser*.lua`, `plasma*.lua`, `railgun*.lua`, `rockets*.lua`) and from module marks, not from the ship row; this is consistent with community reports that editing the ship changes speed and energy but not damage.
* Whether the DedicatedServer reads these Lua files directly (architecture §5) or the generated XML only, and whether remote clients need the same numbers for UI/prediction, remains **runtime-testable only** (Q29, Q36).
