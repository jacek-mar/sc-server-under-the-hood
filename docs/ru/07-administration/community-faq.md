## Начало работы

**В: Нужен ли Steam для запуска сервера/клиента?** *(community, plausible)* Steam
служил лишь каналом загрузки и входа через Steam; депо — обычный каталог.
Локальный встроенный сервер принимает любую почту/имя и пароль
и создаёт учётную запись при первом входе. Наш тест использовал копию из Steam
([verification-log](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/verification-log.md) V-5); запуск
скопированного депо без Steam остаётся открытым вопросом (Q20).

**В: Игра пишет «this application does not support remote session».**
*(static, `win64/game.exe` start-up code)* Клиент отказывается запускаться
в сеансе удалённого рабочего стола; переключателя для отключения проверки нет.
Запускайте его на локальном (консольном) рабочем столе машины. Серверные
службы это ограничение не затрагивает.

**В: Вхожу на «localhost» и получаю новую учётную запись первого уровня — где
мой прогресс?** *(community; matches architecture)* Официальной базы больше нет;
у каждого узла своя MongoDB, и каждая учётная запись создаётся пустой. Прогресс
можно воссоздать лишь правками БД узла (см. ниже). Учётные записи не переносятся
между серверами.

**В: Первый запуск медленный / несколько раз появляется «connection to server lost».**
*(observed)* На достаточно мощном ПК узлу нужно менее 90 с для запуска 17 служб;
на двухъядерном ЦП Hub зависает, и службы завершаются. Дождитесь всех служб
перед входом ([verification-log](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/verification-log.md)
V-1, V-5). Закрытие игры, пока окна сервера ещё запускаются, оставляет
старые процессы (корректно остановите Hub, затем `mongod`).

**В: Окно MongoDB закрывается или программа для БД не подключается.** *(community +
file-verified)* В депо входит MongoDB **2.6.12**; современные графические клиенты
отказываются с ней работать. По сообщениям сообщества, NoSQLBooster **3.x (≈3.5.7)**
работает, текущая основная версия — нет. `mongod` должен работать; игра/сервер
необязательны, но не редактируйте данные, пока узел их записывает. У БД нет
аутентификации на 127.0.0.1 ([mongodb.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/06-database/mongodb.md)). В Windows
запрос брандмауэра для отдельного exe или скрытый `cmd /c launch.bat` может
завершить `mongod` — запускайте его напрямую.

**В: Какой графический клиент MongoDB работает?** *(community, S15)* По сообщениям
русского канала, NoSQLBooster **5.2.x** и MongoBooster **3.5.x** подключаются;
свежие версии — нет. Сначала запустите `mongod` и дождитесь полного запуска
сервера, затем подключайтесь. То же ограничение (сервер поддерживает только
сетевой протокол MongoDB 2.6) относится к любому графическому клиенту или
драйверу — см. [mongodb.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/06-database/mongodb.md). В контейнере используйте
образ `mongo:2.6` ([docker.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/docker.md)).

**В: Как подключить клиент к своему узлу или узлу друга?** *(community, S15 +
official page)* На экране входа выберите **server** вместо *localhost*,
введите IP узла и любые логин/пароль (учётная запись создаётся при первом входе).
Указывайте только IP и оставьте в поле порта значение по умолчанию, 3801
*(observed V-9)*. У пользователей, вводивших другой порт из журналов,
подключение не удавалось; 3850 — внутренний порт Hub, а не порт входа
(см. вопрос о портах ниже).

**В: «Network error» / «OnDisconnect reason 0» при подключении к другому ПК.**
*(community, S15)* Большинство сообщений — о первых попытках по локальной сети
или Интернету. Проверяйте в порядке вероятности: (1) отвечены все запросы
брандмауэра/антивируса либо созданы правила для каждого `cloud\*.exe`
([verification-log](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/verification-log.md) V-8);
(2) `cloud.xml` `<Node address=…>` содержит доступный *клиенту* адрес,
а не `127.0.0.1`, и после этого Hub перезапущен (но см. Q30: адрес вне loopback
подозревается как причина аварии боя); (3) доступен диапазон боевых портов
(UDP/TCP 35000+), иначе лобби работает, а бои — нет; (4) сборка игры совпадает
с серверной; (5) только для удалённых игроков: маршрутизатор/NAT узла
перенаправляет порты Hub, LoadBalancer, Shard, чата и боёв (полный набор ещё
сокращается, Q25). Автор Docker-проекта сообщил об аварии DedicatedServer
при начале боя с адресом узла вне loopback (Q30). Игроки из одной страны
сообщали о региональных отключениях примерно через 20 с и обходили их с VPN
(Q26) — пока это не считается неисправностью сервера.

**В: Язык клиента польский/русский, хотя в Steam выбран английский.**
*(community)* Добавьте `-lang ENGLISH` в параметры запуска Steam (`%command%`
заменяется штатной командой, поэтому может стоять в начале или конце).
⚠ Нами не испытано.

## Учётные записи и экономика

**В: Какие поля БД соответствуют валютам?** *(field names file-verified in
[schema.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/06-database/schema.md); mapping from community)*

| В игре | Поле `accounts` |
|---------|------------------|
| Иридий (token credits) | `tokenCredits` (+ `tokenCredits_earnedToday`) |
| Кредиты | `credits` |
| ГС (золото) | `goldCredits` |
| Синергия (общий запас опыта учётной записи) | `accountExpPool` (по сообщениям: счётчик *свободной* синергии не отображался, а при ручной установке значение становилось отрицательным ⚠) |

**В: Почему правка конфигурации Lua не даёт золото?** Балансы хранятся в БД,
а не в `default_platform_config.lua`. Конфигурация содержит лишь *начальные*
значения (например, `premium_on_start`, множители цен) и правила. *(file-verified)*

**В: Почему за день нельзя заработать больше иридия?** `cvars.sv_tokenCreditsDailyLimit
= 1000` в `default_platform_config.lua` (два вхождения) ограничивает token credits
за день; БД отслеживает их в `tokenCredits_earnedToday`. *(file-verified;
effect untested)* — относится к Q12.

**В: Насколько большим можно вручную задать баланс, уровень PvE или ресурс?**
Пока неизвестно — придерживайтесь умеренных значений и по возможности используйте
административную задачу `give` ([admin-tasks-howto](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/admin-tasks-howto.md)).
Сообщения сообщества (S17, ⚠): «слишком большие» балансы становятся
отрицательными, и их нельзя тратить (**Q52**; поля БД — int64, но игра
не принимает пределы валют выше 2 147 483 647 — знаковое 32-разрядное число,
поэтому оставайтесь ниже); очень высокие уровни атаки/защиты PvE
(`unlimPve_playerLevel1/2`) делают корабль неуязвимым с полосами корпуса и щита
`nan` и уроном первого уровня (**Q51**; усиления линейно растут с уровнем без
ограничения в `shared/unlim_pve.lua`); по сообщениям, ресурсы нужно один раз
купить, прежде чем можно редактировать их запись в `items[]` (**Q54**).
Ранг игрока `accountRank` выше 25, по сообщениям, ничего не меняет.
Всё это — открытые предложения тестов в [open-questions](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/08-reverse-engineering/open-questions.md).

**В: Постоянный премиум для администраторов?** `cvars.auth_infinitePremiumForRoles =
"gm;support"` даёт бесконечный премиум учётным записям с `admRole` из списка.
*(file-verified)* Установка `admRole` в БД, возможно, также нужна для
экспериментов сообщества с «GM-командами» ⚠.

**В: Как сделать всё доступным для покупки / дешевле?**
`cvars.store_allowAllItemsForBying = 1`; множители цен кораблей/модулей/
боеприпасов — в начале конфигурации (строки ~110–114). *(file-verified)*
См. [tuning-recipes.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/tuning-recipes.md).

**В: Как выдать премиум на 365 дней?** `accounts.premiumTill` — **время
истечения как метка Unix в миллисекундах** (int64; сопровождающий 2026-10-13
подтвердил, что это метка Unix окончания действия; единица «миллисекунды»
подтверждена статически в `Shard.exe`, те же часы, что у `bannedTill`/`chatMutedTill`).
Значение в секундах («365 дней в секундах» из сообщества, S15) читается как
дата в январе 1970 года — уже истёкшая; это объясняет сообщение «не сработало».
Два способа:

* административная задача (предпочтительно): `{cmd: "give", uid, value: "premiumTill",
  amount: <hours>, reason, ...}` — Shard добавляет `amount` × 3 600 000 мс
  к более позднему из текущего срока и *сейчас* (8 760 ч = 365 дней);
  отрицательное количество сокращает срок (проверки `premium already expired` /
  `premiumTime underflow`) — см. [admin-tasks-howto](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/admin-tasks-howto.md);
* прямая правка: `premiumTill: NumberLong(<epoch ms of the expiry>)`, например
  `NumberLong(Date.now() + 365*24*3600*1000)` в оболочке mongo; клиент
  показывает это после повторного входа (Q32).

**В: Сколько одинаковых уникальных модулей можно поставить на корабль?** *(file-verified,
S15 pointer)* `cvars.store_maxUniqueModules = 3` (обычные корабли) и
`cvars.store_maxUniqueModulesOnPremium = 2` (премиумные) в
`default_platform_config.lua`; комментарии перед ними описывают именно это
ограничение. Увеличьте оба значения, чтобы разрешить больше.

**В: Я изменил характеристики корабля в Lua — почему сработали не все?**
*(community, ⚠ mixed)* Пользователи своих узлов сообщают: скорость, энергия и
манёвренность изменились в бою, а урон, корпус и радар — нет (один пользователь
видел уничтожение с одного попадания). Откуда DedicatedServer берёт значения,
остаётся открытым вопросом (Q29). **Статическая находка (2026-10-11, по файлам):**
числа отдельных кораблей (`hull_health`, `shield_max`, `max_speed`, `energy_*`,
сопротивления, `repair_cost`) находятся *не* в `objects/ships.lua` (там лишь
63 базовых класса), а в экспортированных строках `data/gamedata/def/ex/ship.lua`
и `ship_green.lua` — см. [ship-defs.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/ship-defs.md).
Практический способ *(community, later message)*: найдите там корабль и
проверьте его `inherit` (изменение базового определения влияет на наследников);
базовые `hull_health`, `shield_max`, `max_speed` — не окончательные боевые
значения; меняйте **по одному параметру**, записывая корабль, поле, старое и
новое значение; для видимых в клиенте чисел данные нужны в переопределяющем
`.pak` (отдельные Lua-файлы клиент не читает). Если число в интерфейсе меняется,
а поведение в бою — нет, сервер вычисляет его в другом месте. Помните, что
**изменения затрагивают только запущенный вами сервер** и что после правок
данных (не конфигурации) может понадобиться пересоздать XML (`prepare_shared`)
([tuning-recipes](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/tuning-recipes.md)). По сообщениям,
экстремальные значения приводят к аварии боя (переполнение типа) ⚠.

**В: Можно перенести учётную запись на другой сервер?** Официально — нет.
Теоретически документ БД можно экспортировать/импортировать между узлами —
не испытано (Q18).

**В: Можно перенести прогресс с официальных серверов на свой?** *(b007
J10)* Нет — официальная база учётных записей осталась у разработчиков. На своём
сервере предметы и корабли можно выдать вручную через MongoDB (каждый корабль —
элемент `accounts.vessels` с уникальным `vid`; инопланетным кораблям и кораблям
потасовок также нужен `data/gamedata/def/objects/gameplay_leviathan.lua` на сервере
**и** клиентах для места и значка в дереве — рецепт сообщества, не проверено).

**В: Игрок забыл пароль — может администратор его сбросить?** *(observed V-9;
b007 J1/J2)* В клиенте нет функции смены пароля. Сохранённое значение
(`accounts.password`, 64 шестнадцатеричных символа) не зависит от учётной записи:
две записи с одинаковым паролем хранят одинаковое значение, поэтому копирование
значения из записи с известным паролем задаёт этот пароль (тест V-10
ожидается). Пароли используются ровно в том виде, как введены — пробел
в конце является частью пароля (сообщество).

## Бои, боты, PvE

**В: Боты слабые (T1–T3) / только один противник ИИ / хочу больше ботов.**
`cvars.mm_botsCount` (значение в файле **6**, диапазон 0..31) — основа;
каждая очередь может переопределить её через `special.botsCount`.
Учётные записи низкого уровня попадают в очереди *новичков* (`queueFlags.newbie = 1`,
например, строки 412/448/734/782), поэтому правки других очередей кажутся
«неработающими» до повышения уровня. Качество бота задаёт пресет:
`botPresetType` / `botPresetNames` / `botPresetByTier`
([tuning-recipes](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/tuning-recipes.md)). *(file-verified keys;
effects ⚠)* По сообщениям, при очень большом числе ботов они замирают
(на несколько секунд перестают стрелять) — возможно, ограничение обновления
ИИ в одном процессе DedicatedServer ⚠.

**В: Почему существуют две копии одной очереди?** `queuesConfig` и
`queuesConfigLo`, выбираемые по `mm_lowOnlineLo/Hi` (250/300 игроков онлайн).
*(file-verified)*

**В: Штраф возрождения?** Очереди новичков задают `sv_respawnTimePenalty = 0`
через `ConfigureDediServerFlags`. *(file-verified)*

**В: Уровень миссии PvE остаётся 1.** По сообщениям сообщества, штатно
прохождение миссии открывает следующий уровень. Есть ли серверный ключ
для принудительной установки — открытый вопрос.

**В: Спецоперации закрыты / какая когда запускается?** Спецоперации — это
PvE-**рейды** (`raidQueue`, `pve_raid = 1`). Клиент открывает вход с **ранга
учётной записи 7** (`UI.rankLocks` в `data/ui/scripts/work/uigamedefs.lua`;
миссии PvE — 4, свой бой — 5); полученная операция зависит от **ранга корабля**
(Инопланетный эсминец 7–9 / 10–12 / 13–17, Осквернитель 10–17,
Возвращение в Эдем 13–17) и недельного **расписания рейдов** в
`cloud/data/aux_limits.xml` (одна операция каждый чётный час недели).
Штатный узел позволяет начать рейд **одному игроку** (`mm_raidSquadFilter` 0).
*(file-verified + observed, [V-12](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/verification-log.md))*

**В: Можно добавить ботов в спецоперации?** **Не через конфигурацию.**
MatchMaker задаёт рейду 0 ботов независимо от очереди; cvar боевого сервера
это не изменили, а свой бой PvE не предлагает ни рейдов, ни настройки ботов
(выбор 8–24 ботов есть только в своём бою PvP). *(observed, V-12; open: Q50)*

**В: Послебоевая добыча пишет «Nothing found» / пропускается.** Это наблюдали
несколько операторов локальных и публичных узлов. Сообщаемая частичная причина:
имена определений таблиц добычи с суффиксом `_v3` и без него (`_1_3` и `_1_3_v3`)
в `data/gamedata/shared/loot_tables.lua`, а также зависимость от ранга.
⚠ Открыто — исследовать с `sv_lootFailChance` (Q12).

## События, боевой пропуск, специальные валюты

**В: Ксеночипы?** Существуют лишь во время соответствующего события; остаток
уничтожается по его завершении (текст в игре, по сообщениям сообщества).
Периоды событий — даты в `default_platform_config.lua`; поставляемые даты
уже в прошлом. По сообщениям, события запускаются, но купленные чипы не
отображались/не использовались — полный рецепт **неизвестен** ⚠
(в `battle_pass.lua` этапы 2–4 закомментированы).

**В: Локальный сервер пишет «authorisation error»; окна bat сразу закрываются.**
*(community, b006 I12; cause ⚠ unknown)* Сначала проверьте, что MongoDB
действительно работает: `cloud\mongodb\launch.bat` хранит БД в
`%LOCALAPPDATA%\Targem\StarConflict\cloud\mongodb\data` *(file)*. Один оператор
устранил ошибку, указав в `MONGO_DATA_PATH` этого файла каталог рядом с
`launch.bat`. Путь профиля, который MongoDB 2.6 не может использовать
(права, необычные символы), — наша неподтверждённая догадка. Запустите
`mongod.exe` из консоли, чтобы увидеть текст ошибки вместо исчезающего окна.

**В: Как увидеть консольные окна всех служб?** *(file; effect ⚠
untested)* В `cloud/data/hub.cfg` строка 6 задаёт `hub_detachChildProcesses 1`
(«запускать серверные приложения без окна»). Установка `0`, предпочтительно
в `hub_local.cfg`, должна заставить Hub запускать каждую службу с отдельной
консолью. Журналы служб в любом случае находятся в каталоге профиля
([administration](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/administration.md)).

**В: Включил этапы боевого пропуска 2–3 в Lua, но завершение этапа фазы 2 даёт ошибку.**
*(file-verified, b007 J3)* Игре нужны этапы и в сгенерированном
`cloud/data/battle_pass.xml`. Поставляемый XML содержит только наборы этапа 1,
а `data/gamedata/shared/battle_pass.lua` определяет этапы 1–4 (2–4
закомментированы). Включив этапы в Lua, пересоздайте XML
(`prepare_shared.bat` — *inferred* по именам выходных файлов в исполняемом
файле, нужна работающая MongoDB) либо используйте XML с записями
`Bundle_Battle_Pass_2_*` / `_3_*`; перезапустите узел.

**В: Можно удалить не понравившийся класс сид-чипов (autogen)?** *(file, b007
J5)* Нет. Комментарий в `data/gamedata/shared/autogen.lua` (переведён с
русского в оригинале) говорит: классы нельзя удалять, иначе уже созданные
модули становятся недействительными и их больше нельзя пересоздать.
Меняйте значения; правки определений аффиксов влияют лишь на новые чипы.

## Несколько пользователей / размещение сервера

**В: После изменения баланса/кораблей на сервере игроки с обычным клиентом
не могут войти (или игра падает при входе в бой).** *(community, b006 I4, two hosts)*
Правки в `data/gamedata/**` (общий Lua) затрагивают и данные клиента. Это
**не** проверка хеша данных Shard (на штатном узле она открыта). Вероятная
причина — расхождение данных: клиент строит определения по своим файлам,
а магазин получает с сервера, и идентификаторы наборов/аватаров/девизов/
расходников в магазине назначаются в порядке загрузки, поэтому вставка или
удаление определения сдвигает идентификаторы (⚠ гипотеза;
`tools/data_drift_check.py` сообщает о таких сдвигах). Добавление или
переименование определений также вызывает проверку определений сущностей
боевого сервера ([hub-protocol-and-framing](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/08-reverse-engineering/hub-protocol-and-framing.md) §6a).
Добавляйте определения в конец семейства либо задавайте явные идентификаторы.
Либо поставляйте всем игрокам одинаковые файлы (операторы делают для этого
лаунчеры), либо по возможности ограничьтесь серверными файлами
(`cloud/data/*`, конфигурация платформы).

**В: Могут клиенты игроков сразу запускаться с адресом моего сервера?**
Не документировано. Наводка: конфигурация клиента выполняет `exec address.cfg`,
но файл не поставляется (Q46, не испытано). Сейчас игроки вводят адрес вручную.
Один оператор предлагает короткий псевдоним в файле Windows `hosts`.

**В: Могут друзья подключиться к моему серверу?** *(community, architecture)*
Да: они вводят IP/порт узла на экране входа; локальные правки действуют
только у оператора. Откройте порты из [architecture.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/03-architecture/architecture.md);
HTTP-порт состояния Hub и Mongo не следует открывать наружу. У одного
пользователя попытка по локальной сети не удалась (причина неизвестна, Q2/Q3).

**В: Можно разместить сервер в Docker / на Linux VPS?** *(community, S16; analysed
by us)* Да, с оговорками: образ сообщества запускает 32-разрядные службы
под Wine, использует нативные MongoDB 2.6 и Redis, исправляет исполняемые файлы
и публикует широкий диапазон портов. Оценка, риски и схема с усиленной
защитой: [docker.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/docker.md).

**В: Какое нужно оборудование?** Оценки сообщества: современный ПК с 6–12
ядрами и 16–128 ГБ может обслуживать несколько сотен игроков ⚠ (не измерялось).
Наш узел: 19 процессов, ~1,2 ГБ в простое. Оператор (S15) оценивает расход
в ≈ 1,5–2 ГБ ОЗУ на экземпляр зоны открытого мира, по одному на каждую
локацию, и говорит, что арендуемой машины класса VPS с 3 ядрами/28 ГБ хватает
на ~500 игроков онлайн ⚠ — нами ни то ни другое не измерено (DK-8).

**В: Несколько регионов / отдельная БД?** Сообщество: адрес БД можно задать
недокументированным блоком в `common_local.cfg`, получая одну БД шарда
со службами по регионам ⚠ (Q4/Q9 открыты). Игра не защищает подключение
к Mongo (нет пароля) — держите его в частной сети/VPN.

**В: Можно использовать внешний вход/аутентификацию?** Документированной
точки интеграции нет; учётные записи создаются при первом входе в БД узла ⚠.

**В: Какие порты должны быть доступны игроку из локальной сети/извне?** *(observed V-9)*
TCP 3801 и 3802 (вход, ангар), TCP 3815 для чата (без него чат молча
не работает — ошибки на экране нет) и UDP от 35000, по порту на каждый
одновременный бой. Порт Hub 3850 — внутренний. На экране входа выберите
`server` и введите адрес узла; поле порта по умолчанию содержит 3801.
Подробности: [verification-log V-9](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/04-installation/verification-log.md),
[security §6.2](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/security.md) (проверенный список портов).

### Дополнения пакета 008 (2026-10-12)

* **Как подключиться к серверу сообщества?** Запустите `win64\game.exe`
  напрямую (запуск из Steam также запускает локальный сервер и его окна).
  На экране входа переключите выбор внизу слева с `localhost` на сервер,
  введите адрес узла (поле порта уже содержит 3801) и войдите с **именем**,
  а не почтой — на большинстве серверов новое имя создаёт учётную запись.
  Адрес нужно вводить каждый раз; предустановка `address.cfg` не действует
  (тест V-10). *(community, consistent with V-9)*
* **Можно использовать официальную учётную запись?** Нет — официальная БД
  не опубликована. У каждого сервера сообщества свои записи. **Никогда не
  используйте повторно пароль от официальной или любой другой учётной записи**:
  серверы хранят быстрый хеш без соли, поэтому оператор может проверять
  догадки ([security S-07](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/security.md)).
* **Безопасно загружать клиентские файлы с сервера или лаунчера?** Относитесь
  к ним как к программам: Lua игры, вероятно, может выполнять нативный код
  (S-29, Q47). Предпочитайте неизменённые файлы Steam и доверенные источники.
* **Я сломал сгенерированный файл, например `autogen.xml`.** Он поставляется
  в `cloud/data`; восстановите его из депо Steam (проверка файлов игры или
  копия из чистой установки) либо пересоздайте через `prepare_shared`.
  Перед правкой сгенерированных файлов сохраняйте резервные копии.

  пакет 010). *(file-verified key; effect reported)*
* **Должен сайт сервера записывать награды прямо в MongoDB?** Прямые правки
  доходят до игрока только после нового входа (Q32), а служба, держащая
  учётную запись в памяти, может записать обратно свою копию ⚠ (не испытано).
  Очередь административных задач (`give`, `adminMail`) — интерфейс, который

### Обновление руководства сообщества (S11, 2026-10-14)

  ошибку (нет запятой *между* записями, несбалансированные скобки или кавычки);

  только при полном запуске; по сообщениям, запущенный клиентом локальный
  Hub продолжает работать, и следующий запуск подключается к нему —

### Дополнения пакета 011 (2026-10-14)

* **Как безопасно редактировать БД?** Остановите игру и сервер, запустите
  только MongoDB, внесите изменения клиентом MongoDB (сообщество использует

  в памяти (Q32). Для работающего сервера используйте очередь административных

  *(observed V-10/V-11 for admin tasks; overwrite not tested)*
* **Запуск игры из Steam не удаётся, пока открыто моё окно БД.** Steam
  выполняет `win64/game.exe -launchLocalServer`, затем клиент запускает
  собственную MongoDB (тот же каталог данных, порт 27017) и Hub из

  Steam восстанавливает файл. *(observed V-5; file)*
* **Меня выбрасывает при покупке или изготовлении.** Это ограничитель запросов
  Shard: `set sm_overloadCounterLimit 20` в `cloud/data/shard.cfg`
  (строка 6). Увеличьте значение там или в `shard_local.cfg`; очень большие

* **Что получают новые учётные записи?** `data/gamedata/shared/starter_pack.lua`

  модулями и боевым слотом) → `prepare_shared` → `cloud/data/starter_pack.xml`.
  В поставке: один корабль T1, без валют. Начальная синергия: cvar
  `synergy_on_start` (по умолчанию 0); `gold_on_start` и прочие — в Lua
  платформы ([tuning-recipes](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/tuning-recipes.md), пакет 011).
  *(file)*
* **Почему чаще всего попадаются режимы с бомбой и капитанами?** `levelsDesc`
  очереди перечисляет допустимые идентификаторы режимов для каждой карты;
  поставляемые аркадные очереди малого онлайна **и кооперативные против ИИ**
  используют `{4,9,11}` (контроль маяков, sentinel/«Разведка боем», взрыв базы/«Детонация»)

  боты плохо обращаются с бомбой, и убирают 11 из кооператива (Q61). *(file; bot
  behaviour reported)*
* **Изменил карму и теперь не могу войти.** Уровни кармы и враждебность полиции

  уровень корабля вне диапазона локации (Q60). *(static; refusal reported)*
* **Как выдать турнирные окраски?** Окраски, узоры и декали — *элементы
  оформления* (`shared/vessel_custom_elements.lua`, например `4cb_tournament`);
  наклейки — в `shared/vessel_stickers.lua` (группа `TOURNAMENT`). Выдавайте
  административной задачей `giveVesselCustomElement` (поля `uid` и `item` =
  имя элемента; привилегия `propertyEdit`), административным письмом
  (тип вложения 16 `LAT_CUSTOM_ELEMENT`) либо набором с этим элементом
  ([admin-tasks-howto](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/admin-tasks-howto.md)) ⚠ не испытано.
* **Игрок на новом ПК не может отправлять почту или торговать.** Почте
  (и торговле через неё) нужен `antibotCounter` 50, а на новой машине —
  достаточный `machineAntibotCounter`, иначе запрашивается двухэтапная
  авторизация (`shard_is2StepAuthForMailSendingNeeded`, по умолчанию 1),
  которую сервер сообщества предоставить не может. Задайте 0 в
  `shard_local.cfg` ([event-ships](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/event-ships-mail-and-clan-ship.md)).
  *(static)*
* **Почему нельзя поставить сид-чипы на инопланетные корпуса?** Эти определения
  (биоморфы, боссы открытого мира и пришельцы) не объявляют слотов сид-чипов;
  создаваемые корпуса рангов 14/15 объявляют 4 и 5, обычные корабли игроков —
  по одному на ступень технологического уровня начиная с T2 (Q49).
  *(file, inheritance checked)*

* **MongoDB запускается и сразу закрывается / localhost «cannot connect».**

* **Какой графический клиент MongoDB работает?** Поставляемая MongoDB 2.6.12
  слишком стара для современных программ; игроки используют NoSQLBooster

* **Что значит «Server under heavy load»?** Это текст клиента при ожидании
  входа в очереди (`login_connecting_desc`), а не измерение нагрузки.
  Обычно службы (ещё) не работают, остался запущенный клиентом сервер
  прошлого сеанса либо правка конфигурации сломала запуск — проверьте

  игры в Steam. Обычный файл с тем же путём, что у упакованного, не вызывает

* **Корабли рангов 16–17 не находят бой против ИИ и не получают добычи.**

* **Миссии PvE с другом не запускаются.** Оба блока очередей PvE поставляются
  с `maxPlayers = 1`; операторы задают 4 (и `botsCount` в `special`
  для союзных ботов). *(file key; effect reported)*
* **Как запустить второй клиент?** Клиент отказывается запускать вторую копию;
  `game.exe -multiCopies` пропускает проверку (Q31). *(static)*
* **Можно разместить сервер для друзей через Интернет?** Клиентам нужны
  TCP 3801, 3802, 3815 и UDP от 35000; адрес узла должен быть доступен
  клиентам **и** принадлежать ПК. За маршрутизатором или CGNAT это
  противоречие (Q62); VPS, общий для игроков VPN или игра в локальной сети
  обходят проблему. *(observed V-9; NAT part open)* Статическая наводка
  (2026-10-14): у служб есть настройки «переопределения внешнего узла» —
  `net_overrideShardAddr`, `net_overrideChatServerAddr` (LoadBalancer) и
  `net_overrideDedicatedServerAddr` (Shard), каждая — имя узла или IP без
  порта, задаются в `loadbalancer_local.cfg` / `shard_local.cfg`.
  Настройка Shard применяется всегда, если задана; настройки LoadBalancer,
  видимо, лишь когда есть выбор из нескольких Shard/серверов чата ⚠ —
  не испытано, см. Q62.
* **Достижения Steam ещё открываются?** Нет. Клиент и службы поставляются
  без библиотеки Steamworks, поэтому сообщать о достижениях в Steam некому. *(static)*
* **Почему премиум пропал после установки далёкой будущей даты?** Отображение
  оставшегося времени в клиенте сохраняет лишь 32 бита оставшихся секунд,
  поэтому 68 лет и больше показываются как ноль (1 января 2100 слишком
  далеко; «до 2063» работает). Сама проверка срока использует полное
  значение, так что премиум не истёк — ошибается лишь отображение.
  Задавайте `premiumTill` менее чем примерно на 68 лет вперёд (например,
  на 50) либо используйте `auth_infinitePremiumForRoles` (Q63). *(static)*
* **Можно вернуть официальную учётную запись?** Нет — официальные данные
  не опубликованы. Никогда не используйте пароль Gaijin на серверах сообщества (S-07).

## Модификации

**В: Добавил новый корабль или предмет. Нужны ли игрокам мои файлы?** Да.
Добавление или переименование определений меняет хеш определений сущностей,
который боевой сервер сравнивает с клиентским; клиент без тех же определений
получает отказ `DR_BAD_GAMEDATA_VERSION`, и эту проверку нельзя отключить
([hub-protocol-and-framing §6a](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/08-reverse-engineering/hub-protocol-and-framing.md)).
Изменение только *значений* существующих определений (например, прочности
корпуса) не меняет хеш; в бою действуют значения сервера, а в ангаре видны
собственные значения клиента (V-10). *(static analysis + observed)*

**В: Нужны ли клиенту мои правки?** Правки серверных данных (Lua/XML в
`cloud/` и `data/gamedata`) использует ваш узел; удалённые клиенты получают
лишь серверное поведение. Работа с клиентскими ресурсами/моделями — отдельно
(TPAK, см. [tpak-format.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/08-reverse-engineering/tpak-format.md)); по
сообщениям, сетки можно обрабатывать в Blender ⚠ (не проверено).

административная задача `giveAutogenModule` выдаёт такой модуль

Смысл полей пока не документирован.

**В: Можно усилить ботов для игроков высоких рангов?** Задайте пресет
для каждого диапазона рангов в шаблоне очереди (`special.botPresetNames`);
пример в [bot-presets](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/bot-presets.md), раздел 5.
Повреждённый блок молча игнорируется — сначала проверьте на одной очереди
либо выполните [`tools/queue_lint.py`](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/config-validation-tools.md).
Если заданы и `botPresetByTier`, и `botPresetNames`, таблица технологических
уровней имеет приоритет; список означает случайный выбор.

**В: Как получить детали кораблей событий (Helicon, Salyut)?** Статический
анализ ([подробности](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/event-ships-mail-and-clan-ship.md)):
детали Salyut поступали из наборов события, чертежа и заданий события;
для деталей Helicon в поставляемых данных нет источника. По сообщениям,
у деталей нет интерфейса магазина и цен; добавьте определения в запись
БД либо измените рецепт изготовления (`def/ex/craft.lua`). См.
[tuning-recipes](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/tuning-recipes.md) (пакет 005) и Q34.

**В: Где рецепты изготовления?** *(file-verified, b010 N3)* Чертежи:
определения `BP_*` в `data/gamedata/def/ex/craft.lua` (`craft_result`,
`craft_ingredients` с `def` и `count`); корабли из деталей:
`craftable_reagents` в `def/ex/ship.lua`. `store.xml` хранит лишь
скомпилированную копию — меняйте Lua, затем выполняйте `prepare_shared`.
`Iridium_plate` — ресурс «Металлическая заготовка», а не иридий.

**В: У нового предмета/корабля пустое имя или необработанный текст.** *(file, B-8)*
Автоматических имён у определений нет: задайте `uiName` (и `uiDesc`) определения
как ключи строк и добавьте их в таблицу строк клиента
`strings/<language>/string.txt` в установке **каждого** игрока. У большинства
определений в игре намеренно нет имени (это внутренние части); имена есть
только у видимых игроку предметов. См. [data-files](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/data-files.md),
«Отображаемые имена определений».

**В: Поставил другую модель на корабль, и у него нет оружия или модулей.**
*(file-verified fields, b010 N6)* Каждый класс корпуса привязывает каждый
слот модуля к именованной кости модели (`slot_bones` в
`data/gamedata/def/objects/ships.lua`, например `gun`, `gun_1`), рядом с
`weapon_slots` и `fire_sectors`. Если в новой модели нет этих костей,
слотам некуда крепиться *(inferred)*. Корпуса боссов и пришельцев,
добавленные как корабли игрока, могут вообще не двигаться (Q49).

**В: Изменил магазин, и сервер больше не запускается.** Обычная причина —
недопустимое имя определения или опечатка (проверьте имена через
[`tools/defname_check.py`](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/config-validation-tools.md)); восстановите файл
(сохраните копию или используйте проверку файлов Steam, которая также
удалит все остальные ваши правки).

**В: Почему игроки не могут отправлять почту / корабли по почте?** Для отправки
нужен антибот-счётчик не ниже 50 (`shard_minAntibotCounterForMailSending`)
и двухэтапная авторизация; корабли пересылать нельзя, детали/ресурсы — можно
([подробности](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/event-ships-mail-and-clan-ship.md)).

**В: Как изменить требования к кораблю корпорации (дредноуту)?**
`cvars.clan_shipBuildHighRanks` (в поставке 3 участника ранга 9),
`clan_shipPartsCanBuild`, `clan_shipUpgradeCanBuild` в `ConfigureClanServer()`;
цены/длительности в `data/gamedata/shared/clan_ship.lua` (`ClanShipKF`).

**В: Как выполнить действия GM (выдать модуль, заблокировать, сбросить)?**
Административные задачи Shard — задания в коллекции Mongo `adminTasks`;
см. [shard-admin-tasks](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/08-reverse-engineering/shard-admin-tasks.md)
и руководство оператора [admin-tasks-howto](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/admin-tasks-howto.md)
(проверенные примеры).

**В: Где найти другие руководства сообщества?** Фан-сайт «The Outpost»
ведёт коллекцию фрагментов *Server Guide Modules*, включая английский
перевод комментариев `default_platform_config.lua` (S17 в
[реестре источников](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/sources/source-register.md); только ссылка).

**В: Может отряд войти в PvP / случайные миссии?** У некоторых операторов,
по сообщениям, не получается. Статический анализ
([matchmaking guide §8](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/05-configuration/matchmaking-guide.md)):
аркадные очереди требуют ранг отряда 1–15, кооперативные — ранг 1–15
и `mmValue` 0–99; записи с вручную добавленными корпусами рангов 16/17
выходят за пределы. Проверка при выполнении ожидается (Q35).

**В: GM-команды / команды чата?** Интерфейса команд чата нет, но исполняемые
файлы содержат инструменты администратора/GM: 58 административных задач
Shard (`ban`, `mute`, `assignRole`, `giveSpecModule`, `unlockAllVesselNodes`,
`copyAccount`, ...) и консольные команды `cheat_*` в QuestServer,
AchievementServer, ClanServer, Universe и боевом сервере (`cheat_giveQuest`,
`cheat_setOwner`, `cheat_equipWeapon`, ...). Полный список с аргументами:
[console-commands.md](https://github.com/jacek-mar/sc-server-under-the-hood/blob/92208619bfea79166f541d909f34c1ec89dc8688/docs/07-administration/console-commands.md) *(static, not yet executed; how to invoke the Shard tasks is Q37)*.
Роли администратора есть и в БД (`admRole`). Наша SSH-консоль движка
документирована в verification-log V-7.
