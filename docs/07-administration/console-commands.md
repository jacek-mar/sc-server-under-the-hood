## 2. Shard admin tasks (`Task_AdminCmd.cpp`)

> Invocation and authorisation: [shard-admin-tasks](../08-reverse-engineering/shard-admin-tasks.md); required privilege per task: [shard-task-privileges](../08-reverse-engineering/shard-task-privileges.md) (generated).

They operate on accounts, clans and services and are the server-side GM/ops toolbox the live operation used (web admin or support tooling; **how a task is invoked: see [shard-admin-tasks.md](../08-reverse-engineering/shard-admin-tasks.md) (Mongo queue `adminTasks`, static answer to Q37). ## 3. Interpretation

* There is no chat-command GM interface in the list; admin power sits in these Shard tasks, which require a caller with a role/privilege (`assignRole`, `assignRolePrivileges`; cvar `auth_infinitePremiumForRoles`). For a community edition the DB fields (`admRole`) are the practical way to grant roles, and the tasks are what a custom web admin would call.
* `giveSpecModule`, `giveVesselCustomElement`, `giveTitle`, `unlockAllVesselNodes`, `giveFreeSpace` explain the community 'unlock everything' wishes without editing Mongo by hand; `copyAccount` / `copyNewAccount` are the account clone mechanism (Q18).
* `sendCheatToUniverse`, `resetUniversesCounter` act on the open-world Universe service.
